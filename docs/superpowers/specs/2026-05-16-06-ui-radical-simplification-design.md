# 06. UI極限シンプル化（横断指針）

改善案: ⑥ UI極限シンプル化

## 背景
- 足立氏: 「ダッシュボードすら通じない人が99%。いまだにFAXの世界。160人中まともに会話できるのは自分一人」
- ターゲット税理士の多くはITリテラシーが極めて低い。専門用語、抽象概念、多階層メニューは即離脱を招く。
- 機能数より「触ってすぐ動く」が最優先。

## 性質
これは**横断指針**。単独機能ではなく、全ビューの実装時に従うべきルール。
他スペック（01〜05, 07）の実装PRでこの指針への準拠をレビュー観点とする。

## 本番アーキとの関係
- API レスポンスの文言は**サーバ側で英語コードを返し、クライアント側 `labels` で日本語化**
- これによりサーバ側で技術用語が混入してもフロントで吸収できる
- 例: API は `{ "stage": "awaiting_approval" }` を返し、フロントが `labels.stage.awaiting_approval = '所長に見てもらい待ち'` を表示

## 5つの原則

### P1. 専門用語の完全排除
**禁止語（画面に出さない）**: ダッシュボード, KPI, ワークフロー, ステージ, ロール, OAuth, API, RAG, LLM, MCP, サマリー, セグメント, トリガー, モーダル, タブ, ペイン, レコード, エンティティ, スキーマ

**置換例**:
- 「ダッシュボード」→「いま見るところ」
- 「KPI」→「今月の数字」
- 「ステージ」→「いまの状況」
- 「ロール」→「あなたの役割」
- 「ベンダー横断同期」→「freeeとMFの取り込み」
- 「awaiting_approval」→「所長に見てもらい待ち」

ナビ項目名・ボタン文言・トーストメッセージ全てに適用。`script.js` 冒頭の `labels` 定数を中央集約とする。

### P2. 「今日やること」を最上段に
全ビューの最上段は、必ず「今日のあなたが押せる1つのボタン」または「今日見るべき1件」から始める。
- レビューセンター: 最上段は「今日確認すべき1件」
- スタッフ差戻し: 最上段は「いま自分宛に来ている1件」
- 顧問先連絡: 最上段は「今日中に送る1件」
- 進捗: 最上段は「いま止まっている顧問先1社」

該当0件のときも空欄ではなく「今日はありません」のメッセージを大きく出す。

### P3. ボタンは多くて3つ
1つのカードのアクションは最大3つまで。それ以上必要なら「⋯」サブメニューに格納。

### P4. 数字は1段落で読める文に
- 現状: 「87%」「6件」
- 変更後: 「87%まで進みました」「あと6件確認すれば終わります」

### P5. 色とアイコンより、言葉
pill の色分けは維持しつつ、必ず日本語ラベルを併記する（pill 内の英語ステータスは禁止）。
- `urgent` → 「要確認」, `open` → 「作業中」, `done` → 「終わった」
- 既存の `statusLabel(status)` を全描画箇所で使うことを徹底

## 実装上のチェック

### C1. ラベル定数の整備（クライアント側）
`script.js` 冒頭の `labels` を拡張:
```js
const labels = {
  status: { urgent: '要確認', open: '作業中', done: '終わった' },
  stage:  { staff_doing: '担当者が作業中', awaiting_approval: '所長に見てもらい待ち',
            approved: '所長OK', rejected: 'やり直し依頼中' },
  channel:{ email: 'メール', slack: 'Slack', chatwork: 'Chatwork',
            line_works: 'LINE WORKS', messenger: 'Messenger' },
  vendor: { freee: 'freee', mf: 'マネーフォワード', both: 'freeeとMF両方' },
  mode:   { monthly: '毎月のチェック', yearend: '決算のチェック' },
  syncStatus: { ok: '取り込み済み', warn: '一部失敗', error: '取り込めず' },
  threadStatus: { queued: '送信待ち', sent: '送信済み', failed: 'うまく届かず' },
};
```
全 `render*` 関数はこの定数経由で文言を出す。

### C2. ナビ項目名の見直し
| 現状 | 変更案 | dataset.view（不変） |
|---|---|---|
| レビューセンター | 今日見るところ | dashboard |
| 進捗ダッシュボード | 顧問先いちらん | progress |
| スタッフ差戻し | やり直し依頼 | feedback |
| 顧問先連絡 | お客さまに連絡 | portal |
| 試算表増減 | 数字の動き | trends |
| 証憑・消込 | 領収書とお金の照合 | receipts |
| AIルール | 顧問先ごとのチェック | rules |
| 検証メモ | 議事録メモ | validation |
| 運用設定 | 全体の設定 | settings |

**重要**: `data-view` 属性値は変更しない。`renderView()` のディスパッチキー、`appState.activeView` 参照箇所への影響を避けるため、表示テキストのみ差し替える。

### C3. 空状態のメッセージ
全ビューに `empty-state` を整備:
- 「今日はありません」
- 「全部終わっています」
- アイコン1つ + 1文のみ

### C4. ヘルプテキストの常設
各ビュー上部に1行説明を必ず置く（`eyebrow` 上に `helper-line`）。
- 例: 顧問先連絡 → 「ここでお客さまにメールやSlackを送れます」

### C5. APIエラーの自然文化
fetch失敗時のトーストも自然文:
- 例: 通信失敗 → 「ネットがつながっていないかもしれません」
- 例: 送信失敗 → 「お客さまに届きませんでした。もう一度試せます」
- 技術的なエラーコード（4xx, 5xx）は出さない

## index.html 変更
- nav-item の文言変更（C2 採用時）
- 各ビュー上部の `helper-line` 用スロット（必要に応じて render 側で挿入）

## script.js 変更

| 関数 | 変更 |
|---|---|
| `labels` 定数 | C1 のとおり拡張 |
| 全 `render*` 関数 | 直接文字列を出している箇所を `labels.*` 経由に置換 |
| `statusLabel` | `labels.status` を返すよう修正 |
| 新規 `stageLabel`, `channelLabel`, `vendorLabel`, `modeLabel`, `syncStatusLabel`, `threadStatusLabel` | 同様 |
| 各 row-actions | ボタン3つ超過時に「⋯」集約 |
| `empty-state` | 全ビューで使用 |
| 新規 `friendlyError(err)` | API/fetchエラーを自然文に変換 |

## サーバ側ガイドライン
- API レスポンスは英語コードを返す（status, stage, channel など）
- クライアント側 `labels` で日本語化する
- これによりサーバ側で多言語対応が必要になっても柔軟

## styles.css 追加
- `.helper-line { font-size:12px; color:#5c6675; margin-bottom:6px }`
- `.empty-state { padding:40px; text-align:center; font-size:15px; color:#202936 }`
- `.row-overflow-menu { ... }` （ボタン3つ超過時の「⋯」メニュー用）

## スコープ外
- フォントサイズ設定UI
- ハイコントラストモード
- 音声読み上げ最適化
- 多言語対応（基盤は labels 経由で用意するが、辞書は日本語のみ）

- [ ] 1カードのボタンが3つを超えていない
- [ ] サマリーカードの数字に日本語の説明文が添えられている
