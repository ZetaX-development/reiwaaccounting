### spec 20 — 証憑リマインドメール + MF OAuth（2026-05-26〜27）

#### 証憑リマインドメール
- 不足証憑リストをもとに AI が文面を生成
- Nodemailer (Gmail) で送信（SendGrid フォールバック維持）
- `POST /api/clients/:id/messages/reminder` で実行

#### MoneyForward OAuth 連携
- MF Cloud Accounting への OAuth2 フロー実装
  - 認可: `MF_AUTH_BASE_URL/authorize`
  - トークン: `MF_AUTH_BASE_URL/token`
  - データ API: `MF_ACCOUNTING_BASE_URL/api/v3/...`
- アクセストークン自動リフレッシュ（残り 60 秒で更新、`mfRefreshToken` を DB 更新）
- **重要**: MF API は現状 read-only（`journal.write` スコープ未取得）
- UI から「MF に仕訳を登録」ボタン → MF仕訳インポートCSV でダウンロード → 手動インポートで代替

#### その他修正
- LINE 証憑を常に未分類で保存 → 証憑登録画面で顧問先を手動割り当て
- 証憑画像を認証付き Blob ロード（本番で画像が表示されなかった不具合修正）

**関連ファイル**:
- `server/src/routes/mf-oauth.ts`
- `server/src/routes/messages.ts`
- `server/src/routes/vouchers.ts`
- `server/prisma/migrations/20260526090626_spec20_mf_write/`

## アーキテクチャ上の重要な決定事項

1. **MF は read-only**: spec 08 の方針。MF への書き込みは実装禁止。`journal.write` スコープ取得後も要再検討
2. **DB キャッシュなし原則**: MF/freee のデータは毎リクエスト API から取得（`getClientById` でライブオーバーレイ）
3. **Vanilla JS**: フレームワーク化の予定なし。`script.js` 1本（100KB超）で全フロントを管理
4. **ルート明示登録**: `server.ts` の `buildApp()` に明示的に `register`（自動ロードなし）。新ルート追加時は必ずここに追記
5. **テスト**: Prisma/DB はモックしない。外部 API（OpenAI/LINE等）はモック OK
